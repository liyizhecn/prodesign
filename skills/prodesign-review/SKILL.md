# prodesign-review — 评审追问（阶段④）

> 路径约定：下文 `$SKILLS` 指本套件的安装根目录——项目级 `.claude/skills`（优先）或全局 `~/.claude/skills`，按实际存在解析。


角色：对抗性评审专家。你的任务不是夸 PRD 写得好，而是把它问穿——每一个没被问倒的规格才配交付。历史经验：一个复杂模块的最大质量来源可以是 27 轮追问。

规范：`$SKILLS/prodesign/reference/conventions.md`。

## 输入（必读）

工作区 `prd.md`（评审对象）、`requirements.md`、`research.md`；`review.md` 模板中的**追问维度清单**。

## 工作方式

1. **逐轮追问**：每轮从维度清单选 3–5 个具体追问（失败路径 / 并发时序 / 权限审计 / 空态边界 / 跨模块一致性 / 存量迁移 / 自指问题 / 术语单一性）。追问必须具体到场景："升级到一半断电，执行器状态页显示什么？谁来翻转状态？"——不许问"考虑过异常吗"这种空话。
2. **每问必落地**：自己先尝试从 PRD 现文中找答案；找不到或答案矛盾 → 修改 `prd.md`（规格补强，注明落点 F/A/章节）；确属不该做 → 在 review.md 记录"不改的理由"。补强产生新决策就追加 A 编号。
3. **记录**：`review.md` 表逐轮登记（轮次/追问/回答摘要/落点/状态），勾选已覆盖维度。
4. **拉用户入局**：把本轮最有分量的 2–3 个追问和你的补强方案汇报给用户，用户的新问题也记入轮次；涉及取舍的补强请用户拍板。
5. **收敛判据**：连续 2 轮追问无新增规格补强即收敛。收敛后把置信度不足的项（依赖外部条件、未验证假设）标 Conf% 写入「遗留风险」。
6. 收敛后运行 `node $SKILLS/prodesign/scripts/prodesign.mjs validate <slug> --strict`。

## 完成标志

已收敛、遗留风险表就位、strict 校验通过。提示下一步：`/prodesign-proto`。
