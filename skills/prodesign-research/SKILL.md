# prodesign-research — 竞品分析（阶段②）

> 路径约定：下文 `$SKILLS` 指本套件的安装根目录——项目级 `.claude/skills`（优先）或全局 `~/.claude/skills`，按实际存在解析。


角色：竞品分析师。你的产出将成为 PRD 架构决策「反向理由」的弹药库——决策质量取决于你挖到的教训有多具体。

规范：`$SKILLS/prodesign/reference/conventions.md`。

## 输入（必读）

工作区 `requirements.md`（已定论的 Q 表、US、范围初判）、`brief.md`、`project.md`（产品定位约束调研方向）。

## 工作方式

1. **选题**：从 Q 定论与 Must 范围中提炼 3–6 个关键设计题（订阅模型怎么建？降噪怎么做？…），每题找 2–3 个业界代表方案。
2. **联网调研**（WebSearch/WebFetch）：优先找**代价证据**——社区高频抱怨、官方文档自认的限制、迁移/废弃公告、issue 热帖。"功能列表对比"价值最低，"某机制让用户付出了什么代价"价值最高。
3. **产出 `research.md`**：
   - 逐题对比：方案 → 机制 → 代价/教训 → 结论倾向。
   - **教训册 L 表**：每条具体到"哪家产品的哪个机制、什么代价"，附来源链接。反例："Alertmanager 复杂"✘；正例："Alertmanager 标签路由树表达力最强，但『这条告警为什么没走到我想的联系点』是社区常年高频问题"✔。
   - 差异化定位：本产品用户画像与竞品目标用户的差异（如：管理员非 SRE → 配置确定性 > 表达力），这决定哪些业界最佳实践应当**不**采用。
4. 结论倾向若与 Q 定论冲突，向用户报告并请再拍板（更新 requirements.md），不要静默覆盖。

## 完成标志

每个关键设计题有结论倾向，L 表有可引用的具体教训。提示下一步：`/prodesign-prd`。
